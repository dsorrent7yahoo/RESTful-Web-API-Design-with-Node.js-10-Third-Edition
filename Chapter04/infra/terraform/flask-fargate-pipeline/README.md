# Flask Docker -> Fargate Terraform Pipeline

This Terraform stack provisions a production-oriented CI/CD path for the Flask backend:

- ECR repository for container images
- ECS Fargate cluster/service/task definition
- ALB + target group + listener
- CodeBuild project that builds/pushes Docker images
- CodePipeline (GitHub source via CodeStar connection -> build -> ECS deploy)
- IAM roles/policies for ECS, CodeBuild, and CodePipeline

## Prerequisites

- Terraform >= 1.6
- AWS credentials configured locally
- Existing VPC and public/private subnets
- CodeStar Connection to GitHub in the target region

## Configure

1. Copy example vars:

```bash
cp terraform.tfvars.example terraform.tfvars
```

2. Fill required values:
- `github_connection_arn`
- `github_full_repository_id`
- `vpc_id`
- `public_subnet_ids`
- `private_subnet_ids`

3. Put secrets in SSM/Secrets Manager and map ARNs in `container_secrets`.

## Deploy

```bash
terraform init
terraform plan -out tfplan
terraform apply tfplan
```

After apply, use output `alb_dns_name` for API access.

## Security and Config Planning

- Put sensitive values (`JWT_SECRET`, `SMTP_PASSWORD`, etc.) in `container_secrets`.
- Keep non-sensitive settings in `container_environment`.
- Scale via `desired_count`, `ecs_task_cpu`, and `ecs_task_memory`.
- Restrict public ingress with `alb_ingress_cidr_blocks`.
- For multiple environments, use one tfvars per environment (for example: `dev.tfvars`, `stage.tfvars`, `prod.tfvars`).

## Notes

- ECS deploy stage consumes `imagedefinitions.json` generated by buildspec.
- Current task role policy uses broad DynamoDB access for simplicity; tighten to specific table ARNs when ready.
- For HTTPS, add ACM certificate + HTTPS listener and redirect HTTP to HTTPS.
